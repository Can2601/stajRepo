# Licensegate (License Client Application)

`Licensegate` is a secure, Qt Quick (QML) based login application designed to work in tandem with a separate license generator (`license_app`). It performs robust, offline cryptographic validation of `.lic` license files to authenticate users and verify their permissions.

## Features

- **Offline Authentication**: Validates user credentials against cryptographic license files without requiring an internet connection.
- **Advanced Cryptography** (Powered by `libsodium`):
  - **Symmetric Decryption & Tamper Detection**: Uses **XChaCha20-Poly1305** to decrypt the license bundle and ensure it has not been modified.
  - **Asymmetric Signature Verification**: Uses **Ed25519** public-key cryptography to verify that the license was legitimately signed by the genuine `license_app` private key.
  - **Secure Password Validation**: Uses **Argon2id** to verify the user's password securely against the hash stored in the license (without exposing plaintext passwords).
- **Time-Based Access**: Verifies the license expiry date against the current system time.
- **Recent Logins**: Automatically remembers the last 10 successful User IDs for quick access.
- **Dynamic Configuration**: Allows the user to select the directory where `.lic` files are stored at runtime.

## Dependencies

- **Qt 6** (Requires components: `Quick`, `QuickDialogs2`)
- **libsodium** (Secure cryptographic library)
- **CMake** (3.16+)

## Project Structure

- `Main.qml`, `LoginPage.qml`, `WelcomePage.qml` - The Qt Quick user interface.
- `licenseauth.h/.cpp` - The core validation engine that handles decryption, signature verification, and password checks.
- `crypto_utils.h/.cpp` - Helper wrappers for libsodium's encryption/decryption routines.
- `AppSettings.h/.cpp`, `AppConfig.h/.cpp` - Manages application settings (like the configured license directory) and persists them using `QSettings`.
- `recentlogins.h/.cpp` - Handles saving and loading the recent logins history in a JSON format.
- `shared_license_key.h` - Contains the hardcoded **Symmetric Key** (ChaCha20) shared with the license generator.
- `public_license_key.h` - Contains the hardcoded **Public Key** (Ed25519) used to verify signatures. (The private key remains strictly on the generator app).

## How Authentication Works

When a user attempts to log in with an `ID` and `Password`, the application performs a strict validation pipeline:

1. **Locate File**: Searches the configured license directory for `<ID>.lic`.
2. **Read Bundle**: Reads the raw binary format: `[ 24-byte Nonce | Ciphertext | 16-byte Poly1305 MAC ]`.
3. **Decrypt & Verify Integrity**: Uses `XChaCha20-Poly1305` and the `SHARED_LICENSE_KEY`. If the Poly1305 MAC is invalid (meaning the file was tampered with), validation fails immediately.
4. **Parse Envelope**: The decrypted plaintext is parsed as a JSON envelope containing `licenseData` and a `signature`.
5. **Verify Origin (Signature)**: 
   - The `licenseData` JSON object is compacted and hashed using **BLAKE2b**.
   - The `signature` is verified against this hash using the `LICENSE_PUBLIC_KEY` (Ed25519). This proves the file was generated by the true `license_app`.
6. **Verify Password**: The entered password is hashed and compared against the stored **Argon2id** hash in constant time.
7. **Check Expiry**: Ensures the `expiryDate` defined in the license is still valid.
8. **Success**: The user is granted access and their ID is saved to the recent logins list.

## Building and Running

1. Open the `CMakeLists.txt` in Qt Creator.
2. Ensure the `SODIUM_ROOT` path in `CMakeLists.txt` points to your local `libsodium` installation.
3. Configure the project with a MinGW or MSVC 64-bit kit.
4. Build and Run. 

*(Note: To run the application standalone outside of Qt Creator, you must use `windeployqt` to copy the required Qt DLLs into the build directory).*

## Security Note

For educational and developmental purposes, `LICENSE_KEY` and `LICENSE_PUBLIC_KEY` are hardcoded directly in the source headers. In a true production environment, the symmetric key should be securely obfuscated or retrieved from a secure enclave to prevent reverse engineering (using tools like x64dbg or Ghidra).
